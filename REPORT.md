## 5. Сравнение DVC и ClearML

| Критерий | DVC | ClearML |
|---|---|---|
| Где хранится информация о версии | Метаданные `.dvc` в Git | Метаданные Dataset на сервере ClearML |
| Где хранятся файлы | В DVC remote и локальном кэше | В хранилище ClearML Dataset |
| Создание дочерней версии | Изменение данных, `dvc add`, Git commit | `Dataset.create()` с указанием `parent_datasets` |
| Переключение версии | `git switch` и `dvc checkout` | Выбор нужного Dataset по ID |
| Восстановление на чистой машине | Клонирование Git-репозитория и `dvc pull` | Получение Dataset по ID и скачивание файлов |
| Ветвление | Git-ветки с соответствующими версиями DVC | Создание нескольких Dataset-версий от одного родителя |
| Объединение изменений | Git merge с DVC merge driver и проверкой результата | Создание новой версии с нужным составом файлов |
| Связь с Git | Метаданные DVC версионируются в Git | Dataset ID и зависимости хранятся в ClearML |
| Интерфейс | Git и терминал; визуализация зависит от дополнительных инструментов | Веб-интерфейс с версиями и графом зависимостей |

## 6. Ответы на контрольные вопросы

### 1. Что однозначно идентифицирует версию данных в DVC?

Версию данных в DVC описывает метафайл `.dvc`, содержащий информацию о данных и их хеше. Конкретная версия проекта определяется соответствующим Git-коммитом, а хеш позволяет проверить идентичность содержимого данных.

### 2. Почему одного Git-коммита недостаточно для восстановления данных?

Git хранит метафайл `.dvc`, а не сами большие CSV-файлы. Для восстановления нужны также объекты данных в DVC remote или доступном кэше. Если они недоступны, одного Git-коммита недостаточно.

### 3. Чем версия Dataset отличается от Dataset ID в ClearML?

Версия — это обозначение версии датасета, например `1.0.0` или `2.0.0`. Dataset ID — уникальный идентификатор конкретного объекта Dataset в ClearML. По ID можно обратиться к нужному объекту независимо от названия версии.

### 4. Почему `finalize()` не создаёт следующую версию автоматически?

`finalize()` завершает создание текущего Dataset и фиксирует его как готовый к использованию. Для создания другой версии нужно отдельно вызвать `Dataset.create()`, задать новую версию и при необходимости указать родительский Dataset.

### 5. Как доказать, что ClearML 2.0.0 создана от 1.0.0, а не от 1.1.0?

В коде создания версии `2.0.0` в `parent_datasets` передан ID базовой версии `1.0.0`. Это также нужно подтвердить графом зависимостей ClearML: у `2.0.0` родитель — `1.0.0`, а `1.1.0` не является её предком.

### 6. Что произойдёт, если после `git switch` не выполнить `dvc checkout`?

Git переключит версию метафайла `data.dvc`, но рабочие файлы данных могут остаться от предыдущей версии. Поэтому содержимое CSV может не соответствовать текущему Git-коммиту. `dvc checkout` восстанавливает файлы согласно метаданным текущей версии.

### 7. Когда удобнее использовать DVC, а когда ClearML?

DVC удобен, когда версии данных нужно связывать с Git-коммитами, ветками и воспроизводимыми экспериментами, а хранение файлов организовать в собственном remote.

ClearML удобен, когда нужно управлять датасетами через веб-интерфейс, получать их по ID, отслеживать происхождение версий и видеть зависимости между наборами данных.

### 8.6. Сравнение DVC и ClearML

| Критерий | DVC | ClearML |
|---|---|---|
| Идентификатор версии | Git-коммит и хеши в `.dvc` | Dataset ID |

DVC удобен для совместного версионирования кода и данных, а ClearML — для управления версиями датасетов и просмотра их происхождения.

### 8.7. Ответы на контрольные вопросы

**1. Что идентифицирует версию данных в DVC?**  
Git-коммит и хеши данных в метафайлах DVC.

**2. Почему Git-коммита недостаточно без DVC remote?**  
Git хранит метаданные, но не обязательно сами CSV-файлы. Без кэша или remote данные не восстановить.

**3. Чем версия ClearML отличается от Dataset ID?**  
Версия — обозначение, например `1.0.0`, а Dataset ID — уникальный идентификатор датасета.

**4. Почему `finalize()` не создаёт новую версию?**  
Он завершает текущий датасет. Новую версию нужно создать отдельно через `Dataset.create()`.

**5. Как подтвердить родителя версии 2.0.0?**  
В `parent_datasets` передан ID базовой версии. Это также подтверждается графом зависимостей ClearML.

**6. Что будет, если переключить Git-ветку без `dvc checkout`?**  
Файлы данных могут остаться от предыдущей ветки и не соответствовать текущим метаданным DVC.

**7. Когда использовать DVC, а когда ClearML?**  
DVC удобен для версионирования данных вместе с кодом; ClearML — для управления датасетами по ID и отслеживания их происхождения.

### 8.8. Итог

Проверено восстановление данных через DVC remote и загрузка версий ClearML по Dataset ID. Содержимое файлов, размеры таблиц, хеши и связи между версиями проверены. Оба инструмента позволяют воспроизводимо получать нужные версии данных при наличии доступа к соответствующему хранилищу.
